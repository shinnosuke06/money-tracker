# マネートラッカー

個人用のお金の管理ウェブアプリです。iPhone の Safari(ホーム画面に追加)で使うことを想定しています。

- ビルド不要の静的サイト(HTML / CSS / JavaScript)。`index.html` を開くだけで動きます
- データはブラウザの **localStorage にだけ保存**し、サーバーには送りません
- 金額はすべて **円の整数** で保存します。入力欄では `1000+500` や `1980*3` のような式も使えます(確定時に整数へ計算)
- 表示テーマはライト(白基調)/ ダーク(黒基調)/ 端末に合わせる。どの画面でも右上の丸いボタンで切り替えられます
- Excel で付けていた過去の記録(口座資産の表・カードの引き落とし額の推移)を、貼り付けか CSV で取り込めます
- ホーム画面に追加すると、アプリのように開けます。一度開いたあとは、電波がなくても開けます(PWA)

> このリポジトリには実際の金額・口座情報・個人名・実在の金融機関名や会社名・店名・銘柄名・API キー・個人の URL を入れません。
> サンプルデータとテストデータはすべて架空です(証券A、銘柄X、依頼元A、作業項目X、商品A など。銘柄コードも実在しない形)。

## データ構造の概要

localStorage に次のキーで保存します。

| キー | 中身 | 書き出しに入るか |
|---|---|---|
| `moneyTracker:data` | アプリのデータ本体(1 つの JSON、schemaVersion 14) | 入る(書き出しファイルと同じ形) |
| `moneyTracker:secrets` | 価格取得の URL と Finnhub のキー | 既定では入らない(書き出すときに選んだときだけ) |
| `moneyTracker:ui:*` | 表示の設定(表示テーマ、グラフの切り替え、最後に書き出した日、月末チェックの「確認した」の印・案内を出した日など) | 入らない |
| `moneyTracker:backup` | 上書き・削除の直前のデータ(1 つだけ) | 入らない |
| `moneyTracker:corrupt:<日時>` | 読めなかったデータの控え(あれば) | 入らない |

データ本体は区画ごとに分かれています。

| 区画 | 段階 | 主な中身 |
|---|---|---|
| `monthly` | 1 | 区分(`categories`)、項目(`items`。参考行の印 `reference`・まとめ `group` つき)、月ごとの記録(`records["YYYY-MM"]` に金額・確認日・メモ) |
| `payments` | 2 | 管理中の月、口座(= 月末記録の項目)、支払い・ローンと内訳、入金予定、特別支出、振り分け、履歴 |
| `assets` | 3 | 保有(株・投信)、手入力の資産、総資産の履歴と削除・修正前の履歴、為替、税率や反映先などの設定 |
| `inventory` | 4 | 商品(個数・購入単価・売却優先度・相場の記録・売却の記録)、反映先 |
| `sidejob` | 4 | 依頼元(基本額・作業項目・曜日パターン・入金予定との対応)、日ごとの記録、休む日・追加で出る日 |
| `imports` | 追加 | Excel の取り込みの履歴(最大 30 件)と、直前の取り込みを元に戻すための控え(1 つ) |
| `future` | 5 | 将来予想のプラン(最大 10 件。条件・今の資産の初期値)、見ているプラン、比較する 2 つ |

区画どうしは ID でつながっています(口座 = 月末記録の項目、副業の依頼元 → 支払い管理の入金予定、各機能の反映先 → 月末記録の項目)。全項目の形は「[データ構造(全体)](#データ構造全体schemaversion-9)」にあります。

## 決めたルール

### 個人情報と安全

- 実際の金額・口座情報・個人名・実在の金融機関 / カード / 会社 / 店の名前・銘柄名・API キー・URL・スプレッドシート ID をコードに入れない(リポジトリは公開する。バックアップ・書き出しファイルは `.gitignore` で除外。→ [データとプライバシー](#データとプライバシー))
- サンプルとテストは架空のデータだけ(証券A、銘柄X、依頼元A、作業項目X、商品A など)。銘柄コードも実在しない形(`X101` など)
- データは端末の localStorage だけに保存し、サーバーには送らない。外への通信は「[外への通信](#外への通信)」に書いたものだけ
- 価格取得の URL とキーは設定画面から入力し、データ本体とは別に保存する。JSON の書き出しには既定で含めない
- 表示テーマなどの表示設定は端末ごとに保存し、書き出しに含めない

### 金額と数字

- 金額は**円の整数**で保存・計算する。入力欄では四則演算の式を使える(`eval` は使わない)
- 小数を使うのは、数量(投資信託は「口数 ÷ 1万」)、単価(投資信託の 1 万口あたり、米国株のドル、加重平均の購入単価は小数 2 桁まで)、為替、税率だけ
- 万円の表示(副業)は表示のときだけ丸める(小数 1 桁)。計算は円のまま

### データの形

- データは 1 つの JSON にまとめ、機能ごとに区画を分ける(`MT.store.defineSection`)
- 形を変えるときは `schemaVersion` を上げ、古い版からの移行を足す。古いデータは開いたときに自動で最新の形にし、消さない
- いまのアプリより新しい版のデータを開いたときは、読み取り専用にして上書きしない
- 読めないデータは消さず、`moneyTracker:corrupt:<日時>` に控えを残す
- 消した項目を指している参照(口座・反映先など)は自動で外す

### 上書き・削除と元に戻す

- 読み込み・サンプル・旧アプリの取り込み・Excel の取り込み・全削除・大きな削除の前に、直前のデータを 1 つ保存し、設定の「直前のデータに戻す」で戻せる
- Excel の取り込みは、それとは別に「直前の取り込みを元に戻す」で、その取り込みで書き込んだ所だけを取り込む前に戻せる
- 削除や上書きは、必ず確認を出す
- 旧アプリの取り込みは、読み込む前に件数と「変換できなかった項目」の一覧を見せ、確認してから、その機能の区画だけを置き換える

### 二重入力しない

- 支払い管理の口座は、月末記録の項目をそのまま使う
- 支払い・資産・在庫からは「月末記録に反映」ボタンで月末記録に書き込む(反映先は設定で選ぶ)
- 副業の予想額は、依頼元に対応させた支払い管理の入金予定へ自動で入る(入金済みにした入金は変えない)

### 計算

- 合計は 1 つの明細から出す(支払いは `lines()`、資産は `rows()`)。内訳の合計とすべての合計が一致する
- 月末記録の「参考行」(含み益など)は記録するが、区分の小計・総資産・前月比・推移グラフ・入力状況の案内には含めない
- 資産は、価格が取れていない銘柄を取得単価で代用しない(合計に入れず「価格未取得」と出す)。ポケカは相場の記録がない商品だけ購入単価で評価する
- 売却優先度は「最初に売る / 足りなければ売る / 売りたくない」の 3 つ。既定は株・投信が「足りなければ売る」、手入力の資産が「売りたくない」、ポケカ在庫が「最初に売る」。段階5の取り崩し案で使う

### 画面

- iPhone の Safari が前提。iPhone SE の幅でも崩れないようにする
- 下部タブは 5 つまで(月末記録・支払い・資産・副業・その他)。段階1で決めた「将来予想」「設定」のタブは、副業を足したときに「その他」の中へ移した。新しい画面はタブの中のメニューか「その他」に入口を置く
- 並べ替え:一覧の「並べ替え」で開くダイアログで、左のつまみ(≡)を上下にドラッグするか ↑↓ で動かし、「保存」で決める(`MT.forms.openReorderSheet`)。フォームの中の行(支払いの内訳・副業の作業項目)は、行の ↑↓ で動かす(`MT.forms.moveButtons`)。並びは各配列の順番として保存する。日付で決まる一覧(特別支出・履歴・記録)は並べ替えない
- 色は CSS の変数だけを使い、直書きしない。文字と背景のコントラストは 4.5 以上。プラス・マイナスは色だけでなく符号も付ける(→ [表示テーマと色のきまり](#表示テーマと色のきまり))

### 外部ライブラリ

- ビルドはしない。script は `index.html` に順番に書き、`MT` という 1 つの入れ物に機能を足す。各ファイルには `?v=アプリの版` を付ける(古いファイルがキャッシュから使われないように)

### 更新の届き方

- 設定の「保存しているデータ」の「アプリの版」で、いま動いている版が分かる
- GitHub Pages などでファイルとして開いたときは、起動したときと画面に戻ってきたとき(1 分に 1 回まで)に、公開中の `js/core/store.js` の版をキャッシュを使わずに読んで比べる。違っていれば下に「新しい版(…)があります」と「更新する」を出す。押すと読み直す
- 読み直しで古いファイルが使われないよう、`index.html` の各ファイルには `?v=アプリの版` を付けている
- 1 つの HTML にまとめた試用ページでは確かめない。通信できないときは何も出さない
- iPhone のホーム画面から開いたアプリは、閉じても裏で開いたままのことがある。この仕組みが入る前の版から最初に更新するときは、アプリの切り替え画面で上にスワイプして完全に閉じてから開き直す
- サービスワーカー(`sw.js`)は版(`VERSION` = `APP_VERSION`)ごとにキャッシュを分ける。版が上がると裏で新しい版を用意し、次に開いたとき(または「更新する」を押したとき)に入れ替わり、古い版のキャッシュは消す
- それでも古い画面が残るときは、設定の「アプリの更新」→「最新版に更新」。アプリのファイルのキャッシュとサービスワーカーを外して、ネットから読み直す(データは消えない)
- 版を上げるときは `store.js` の `APP_VERSION`、`index.html` の `?v=`、`sw.js` の `VERSION` をそろえる(`node --test` で確かめられる)

### 機能の足し方(次の段階向け)

1. `js/features/<機能名>/` にファイルを作る
2. データが必要なら `MT.store.defineSection('<区画名>', { create, normalize, finalize?, hasContent, summarize })` で区画を登録する
3. データの形を変えるときは `store.js` の `SCHEMA_VERSION` を上げ、`MT.store.addMigration(古い版, fn)` で変換を登録する
4. 画面は `MT.views['<画面名>'] = { render(container), tab?, unmount? }` で登録する(`#/<画面名>` で開く。準備中の画面と置き換わる)
5. 月替わりのような定期処理は `MT.maintenance` に関数を足す
6. 入力フォームの部品(並べ替えのダイアログ `openReorderSheet` を含む)は `MT.forms`、URL やキーのような秘密の設定は `MT.secrets` を使う
7. 色は下の「表示テーマと色のきまり」の CSS 変数だけを使う(直書きしない。`node --test` で確かめられる)
8. `index.html` に script を追加し、README とテストを更新する
9. 変更を出すたびに `store.js` の `APP_VERSION` を上げ、`index.html` の各ファイルの `?v=` も同じ値にする(`node --test` で確かめられる)。設定の「保存しているデータ」に「アプリの版」として出る

### 表示テーマと色のきまり

テーマは **ライト / ダーク / 端末に合わせる(既定)** の 3 つ。選んだものは端末ごとの表示設定(localStorage の `moneyTracker:ui:theme`)に保存し、データの書き出しには含めません。

- **最初に当てる**:`js/core/theme-boot.js` を `<head>` の中、スタイルシートより前に読み込み、`<html data-theme="light|dark">` と `theme-color` の meta を決める(起動時に一瞬だけ違う色が見えないように)。「端末に合わせる」の判定もここで行い、CSS 側では `prefers-color-scheme` を使わない
- **切り替え**:`MT.theme.set('light' | 'dark' | 'system')`、右上のボタンは `MT.theme.toggle()`(いまの見た目の反対にする)。「端末に合わせる」のときは、iPhone の設定の変化に追従する
- **描き直し**:テーマが変わると、画面を描き直し、`MT.charts.refreshAll()` で表示中のグラフ(ダイアログの中のものも)を新しい色で描き直す。グラフの色はすべて `MT.charts.palette()` で CSS 変数から読む
- **スクショモード**:どちらのテーマでも、面(カード)の上にはっきりした文字で出し、右上のボタンも隠す

#### 色の変数(`css/style.css` の先頭)

ライトの値は `:root`、ダークの値は `:root[data-theme="dark"]` に、同じ名前で書きます。**CSS にも JavaScript にも色を直書きしない**でください(例外は `theme-boot.js` / `theme.js` の theme-color だけ。`--bg` と同じ値にする)。

| 用途 | 変数 |
|---|---|
| 背景・面 | `--bg`(画面)、`--surface`(カード・ダイアログ)、`--surface-2`(区切り・小さいボタン)、`--surface-3`(押したとき) |
| 文字 | `--text`(本文)、`--text-2`(補足)、`--text-3`(注記・目盛り) |
| 枠線 | `--line`、`--line-strong` |
| 強調色 | `--accent`(ボタンの塗り)、`--accent-text`(文字・リンク)、`--accent-soft`(薄い塗り)、`--on-accent`(塗りの上の文字) |
| 金額のプラス・マイナス | `--positive`(緑)・`--on-positive`・`--positive-soft`(薄い塗り)、`--negative`(赤。エラーの文字にも使う)・`--negative-soft`(薄い塗り)。色だけに頼らず `+` / `−` の符号も付ける |
| 危険な操作 | `--danger`(削除ボタンの塗り)、`--on-danger`、`--danger-soft` |
| 注意・お知らせ | `--warn`(点・帯。文字には使わない)、`--warn-text`(注意の文字・アイコン)、`--warn-soft`・`--warn-ink`、`--info-soft` |
| 影・重なり | `--shadow`(カード)、`--shadow-raised`(ダイアログ)、`--shadow-pop`(浮かせた部品・通知)、`--shadow-chip`、`--backdrop` |
| タブ・通知・吹き出し | `--tabbar-bg`、`--toast-bg`・`--toast-text`、`--toast-error-bg`・`--toast-error-text`、`--tooltip-bg`・`--tooltip-text` |
| グラフ | `--series-1`〜`--series-8`(順番を変えない)、`--series-other`、`--chart-grid`(目盛り線)、`--chart-axis`(軸)、`--chart-text`(目盛り・凡例の文字) |

#### 金額の色分け

数字がどれも黒に見えないよう、意味ごとに色を分けます。色だけに頼らず、`+` / `−` の符号か「不足」「残りわずか」などの言葉も一緒に出します。

| 色 | 意味 | 主な場所 |
|---|---|---|
| 緑(`--positive`) | 入るお金・足りている・済んだ | 確保している資金、入金予定(`+`)、振り分けで入る額、引落後予想が足りる口座、差引予測残高(足りる見込み)、履歴の収入・収支のプラス、「済」のチェック、副業の確認済み |
| 赤(`--negative`) | 出ていくお金・不足・未入力 | 残りの支払い(未済)、口座の引き落とし(`−`)、引落後予想・差引予測残高のマイナス(「不足」)、履歴の支払・収支のマイナス、未入力、期日を過ぎた支払い |
| 黄(`--warn-text`・`--warn`) | 注意 | 引き落としがあり、引き落とし後の残りが 1 万円未満(「残りわずか」。口座の左に黄色の線)、引き落とし日が近い支払い |
| 依頼元の色(`--series-1`〜) | どの依頼元か | 副業のカレンダー・絞り込みのボタン・合計・記録・依頼元の一覧(並び順で決まる) |

数字の一覧(支払いの一覧など)は、同じ種類の数字が並ぶので黒のままにし、赤は「未入力」などの注意に取っておきます。

### 古いデータの移行(v1 → v2 → … → v13 → v14)

古いデータを開くと、順番に自動で最新の形になります。ほかの区画はそのまま残ります。

- **v1 → v2**(段階1 → 2):月末記録はそのまま残り、「現金(銀行口座)」区分(`cat_cash`)の項目が支払い管理の口座として最初からつながる(現在残高の初期値は、その項目の最新の月末記録の値)
- **v2 → v3**(段階2 → 3):空の資産管理(`assets`)が足される
- **v3 → v4**(段階3 → 4):空のポケカ在庫(`inventory`)と副業収入(`sidejob`)が足される
- **v4 → v5**(Excel の取り込みの追加):月末記録の項目に参考行の印(`reference: false`)と、空の取り込みの履歴(`imports`)が足される。金額・項目・ほかの区画はそのまま
- **v5 → v6**(副業の追加で出る日の見込み):副業の予定に、空の見込み(`plans`)が足される。作業項目のある記録の内容の文章は、「項目名 + 万円の数」の書き方にそろう
- **v6 → v7**(並べ替え):支払い管理に支払いの並び(`billOrder: "due"`)が足される。これまでどおり引き落とし日順で表示される
- **v7 → v8**(将来予想):空の将来予想(`future`。プランなし)が足される。ほかの区画はそのまま

- **v9 → v10**(総資産の履歴を直す):資産管理に、空の削除・修正前の履歴(`historyTrash`)が足される。今の履歴はそのまま

### 支払い管理の計算ルール

- **口座**:月末記録の項目をそのまま使う(二重入力しない)。「現在残高」は支払い画面で更新し、「月末記録に反映」で月末記録の金額として書き込む。
- **合計の整合**:カテゴリ別の合計・未済・口座ごとの引き落とし・キャッシュフローは、すべて同じ明細行(`lines()`)から計算する。内訳は内訳のカテゴリに、請求額の残り(請求額 − 内訳の合計)は支払いのカテゴリに入る。請求額が空欄なら内訳の合計を使う。内訳の合計が請求額を超えると警告を出す。
- **引落後予想** = 現在残高 + 入金予定(振り分け分・未済)− 引き落とし(未済)。「済」の支払い・入金は、残高に反映済みとして計算から外す。
- **入金済にしたら残高に足す**:入金予定にチェック(入金済)を入れると、その入金額を優先振込先の口座の現在残高に足す(現在残高の日付は今日)。入金予定から外れて口座に入るので、確保している資金と差引予測残高は変わらない。チェックを外すと、足した額を引き戻す。入金済のまま金額や優先振込先を直すと、足した額も直す(編集の「済」も同じ)。優先振込先が無い・金額が未入力の入金は、残高を変えない(お知らせで出す)。
- **そのあと残高を手で直したとき**:足したあとに、その口座の現在残高を手で直したら、手で入れた額を正とする(二重に足さない)。そのあとチェックを外しても引き戻さない(「手で直されているため、そのままにしました」と出す)。入金予定の行には「◯◯の残高に足し済み」と出る。月替わりで「済」が外れるときは、残高はそのまま。
- **未入力**:空欄は 0 として計算する(内訳の一部だけ入れた支払いは、空欄の内訳を 0 にする)。請求額も内訳も空欄の支払い、金額が空欄の入金予定・特別支出、現在残高が空欄の口座は「完全に未入力」として赤で「未入力」と出し(行の左にも赤い線)、概要の「確認してください」と支払いタブの印にも出す。「済」にしたものは出さない。
- **引落後予想の色分け**:引落後予想がマイナスなら赤で「不足」、引き落としがあり残りが 1 万円(`TIGHT_BALANCE`)未満なら黄で「残りわずか」、それ以外は緑(`afterStatus()`)。差引予測残高も同じ決め方で「足りる見込み / 残りわずか / 不足の見込み」と出す。
- **自動振り分け**:口座ごとの不足額(引き落とし − 残高)を 1,000 円単位で切り上げ、優先振込先のある入金から先に埋める。優先振込先のある入金の残りはその口座へ、指定なしの残りは「振り分けなし」。金額を手で直すと「手動」になり、「自動の提案に戻す」で戻せる。
- **キャッシュフロー**:確保している資金(口座残高 + 未済の入金予定)− 残りの支払い(未済)= 差引予測残高。
- **特別支出**:支払月の月は支払いに含める。今後の未済分は「金額 ÷ 支払月までの月数」を 100 円単位で切り上げ、月あたりの必要積立額として表示する。
- **終了月**:終了月を過ぎた支払い・内訳は自動で非表示(データは残る)。
- **並び**:支払いは、はじめは引き落とし日順(日付なしは最後)で、追加や日付の変更のたびに自動で並ぶ。「並べ替え」で保存すると自分で並べた順になり、概要・口座ごとの引き落とし・履歴の明細も同じ順になる。そのあと追加した支払いは、引き落とし日の位置に入る。「引き落とし日順に並べる」で保存すると日付順(自動)に戻る。入金予定は並べた順に表示し、自動振り分けもこの順に入金を使う(優先振込先のある入金が先)。
- **月替わり**:起動時などに月が変わっていたら、前月の状態を履歴に保存し、「済」を外し、変動費(変動の支払い・内訳)と変動の入金の金額を空欄に戻し、振り分けを自動に戻す。

### 資産管理の計算ルール

- **評価額** = 数量 × 現在の単価(米国株は ドル × USD/JPY)。**評価損益** = 評価額 − 取得額(数量 × 平均取得単価)。金額は円の整数に丸める。
- **価格未取得**:一度も価格が取れていない銘柄は「価格未取得」と表示し、どの合計にも入れない(取得単価では代用しない)。取得に失敗した銘柄は、前回取れた価格と日時を残し「取得失敗」と表示する。
- **手残り(税引後)** = 評価額 − 税。税は課税口座(特定・一般)の含み益にだけ税率(既定 20.315%、設定で変更可)をかける。NISA と含み損は 0。手入力の資産は「投資」区分の含み益だけに税をかける。
- **集計**:証券会社別・口座区分別・種別別・売却優先度別は、すべて同じ一覧(`rows()`)から計算するので、どれを足しても合計と一致する。
- **手入力の資産**:評価額と取得額を持ち、含み損益 = 評価額 − 取得額。画面では評価額か含み損益の片方を直すと、もう片方を計算する。
- **売却優先度**:株・投信の既定は「足りなければ売る」、手入力の資産の既定は「売りたくない」。段階5の取り崩し案で使う。
- **買い増し**:新しい平均取得単価 =(今の数量 × 今の単価 + 買う数量 × 買値)÷ 新しい数量。
- **貼り付け**:「コード,銘柄名,数量,取得単価」(タブ区切りも可)。種別はコードの形から推測(国内株:先頭が数字の4文字、投資信託:8文字の英数字、米国株:英字)。同じ証券会社・口座・コードの銘柄があれば買い増しとして合算する。
- **履歴**:「価格を更新」のたびに、その日の総資産と証券会社別の合計を保存する(同じ日は上書き)。前回更新比は、今日より前の最新の記録と比べる。
- **履歴を直す**(`#/assets/history`):記録ごとに、日付と総資産を直すか、削除できる。直す前の記録と削除した記録は「削除・修正前の履歴」(新しいものから 200 件まで)に残り、「元に戻す」で戻せる。戻す日に別の記録があるときは置き換えるかを聞き、置き換えた記録も「置き換え前」として残す。日付は今日より先にできず、ほかの記録と同じ日付にもできない。直した記録には「手で修正」と出る。「完全に消す」と元に戻せない。
- **コメント**:履歴 1 件ごとに、その日のできごと(買った銘柄・相場の大きな動きなど)を 200 文字まで書ける(「履歴を直す」で記録を押す →「コメントを書く」)。グラフでは ◆ の点になり、点を押すと吹き出しに出る。同じ日に価格を更新し直してもコメントは引き継ぐ。削除・元に戻すときもコメントごと動く。
- **同じ日の上書き**:手で直した記録がある日に価格を更新し直すと、新しい値で上書きし、直した記録は「置き換え前」として「削除・修正前の履歴」に残す。
- **開いたときの自動更新**:アプリを開いたとき・ほかのアプリから戻ってきたときに、取りに行ける銘柄があり(国内株・投信は価格取得の URL、米国株は Finnhub のキー)、前回の更新から 30 分以上たっていて、インターネットにつながっていれば、価格を更新する。結果は画面の下に短く出す(取れなかった銘柄の理由は、手で「価格を更新」すると見られる)。1 件も取れなかったときは何も書き込まない。画面の入力欄に入力中なら、終わるまで書き込みを待つ。設定の「価格の自動取得」の「アプリを開いたときに、価格を自動で更新する」で止められる(端末ごとの設定。`moneyTracker:ui:assetsAutoUpdate`)。
- **要確認の目印**:次のどれかに当てはまる記録に付ける(直すかどうかは自分で決める)。前後の両方と 15% 以上ちがい、向きが逆(前後より飛び出て高い・落ち込んで低い)/ 前回から 30% 以上の増減(直前が「飛び出た」記録なら、元に戻っただけなので付けない)/ 価格未取得の銘柄が前回より多い(取得の失敗で合計が小さくなった可能性)/ 総資産が 0 円。ダッシュボードの「履歴を直す」に件数を出す。
- **配当**:1回あたりの配当 = 1株配当 × 数量。税引後は、課税口座なら ×(1 − 税率)、米国株はさらに米国の源泉税 10% を引く(外国税額控除は考えない)。
- **月末記録への反映**:証券会社ごと・口座区分ごと・証券会社×種別(国内株 / 米国株 / 投資信託)ごとのどれかでまとめた評価額の合計を、設定で選んだ月末記録の項目に書き込む。同じ項目を選んだまとまりは合計する。

### ポケカ在庫の計算ルール

- **評価額** = 個数 × 最新の相場(日付がいちばん新しい記録)。相場が無い商品は購入単価で評価する。
- **予定利益** =(最新の相場 − 購入単価)× 在庫。相場が無い商品は 0。**総予定利益**はその合計。
- **確定利益** = 売却ごとの(売却単価 − 売却時点の購入単価)× 個数の合計。売却時点の購入単価(`costAtSale`)は売った時点で記録し、あとで仕入れて単価が変わっても変えない。
- **総支出** = 在庫の購入額(個数 × 購入単価)+ 売った分の購入額。
- **追加**:同じ商品名に追加すると、購入単価を加重平均で出し直す。+/− ボタンは個数だけを直す(購入単価は変えない)。
- **売却**:在庫が足りないときは保存しない。売却を直す・消すと、在庫の個数もそれに合わせて戻る。
- **名前の変更**:既にある名前に変えると、確認のうえ個数・相場の記録・売却の記録を 1 つに統合する(購入単価は個数で加重平均)。
- **反映**:在庫の評価額の合計を、設定で選んだ月末記録の項目に書き込む。売却優先度別の評価額も出す(段階5で使う)。

### 副業収入の計算ルール

- 金額は**円の整数**で保存・計算し、表示のときだけ**万円(小数 1 桁)**に丸める(0.1万の足し算の誤差を出さない)。
- **記録の合計** = 基本額 + 選んだ作業項目の金額。新しい記録では、依頼元の基本額と「既定で選ぶ」作業項目が最初から選ばれる(追加で出る日に見込みを入れてあれば、その基本額と作業項目)。
- **内容の文章**:選んだ作業項目を「項目名 + 金額を万円にした数」にして「、」でつなぐ。例:作業項目K が 10,000円 → 「作業項目K1」、作業項目N が 1,000円 → 「作業項目N0.1」。
- **予定**:依頼元の曜日パターンから、その月の予定日を作る。カレンダーで予定の日をタップすると「休む」になる。予定のない日をタップすると、依頼元と基本額・作業項目を選ぶ画面が開き、「追加で出る日」として、その見込みを予定に入れる(もう一度タップで直す・やめる)。曜日パターンの日を選んだ依頼元なら、休む日を戻して見込みだけ入れる。
- **予想額**:確認済み(入金を確認した記録)/ 予定(未確認の記録 + まだ記録のない予定日の見込み)/ 合計。予定日は今日以降を数え、「追加で出る日」として見込みを入れた日は、今日より前でも記録を作るまでは数える。予定日の見込み = 追加で出る日に選んだ基本額と作業項目、無ければ 1 日の見込み額(基本額 + 既定の作業項目)。
- **カレンダー**:依頼元を絞り込むと、その依頼元の予定を出す(予定の日をタップで「休む」)。「全体」のときは、全部の依頼元の予定(●)・追加で出る日(■)・休む日(○)を依頼元ごとの色で 1 つのカレンダーに出し、日をタップすると依頼元ごとの操作(休む・予定に戻す・見込みを直す・追加で出る日を入れる)を選べる。記録のある日は右上に ●。
- **スクショモード**:タブとボタンを隠し、「YYYY年M月 稼働報告」・依頼元名・合計・日付と金額と内容の一覧だけを出す。
- **支払い管理への連携**:依頼元ごとに、対応する入金予定と入金のタイミング(働いた月の翌月/当月、日にち)を設定する(依頼元の編集で「新しい入金予定を作る」も選べる)。支払い管理で管理中の月の入金予定に、働いた月の予想額(合計)が**自動で入る**(翌月払いなら前の月に働いた分。起動時・画面に戻ったとき・データが変わったときにそろえる)。入金済みにした入金予定は変えない。働いた月の予想が 0 円(記録も予定も無い)のときは、入っている金額を消さない(空欄なら 0 円を入れる)。同じ入金予定に複数の依頼元を対応させると合計する。支払い管理の入金予定には「副業(依頼元)から自動」と出す。
- **来月の入金(予想)**:支払い管理は今月しか管理しないので、翌月払いの今月の働いた分(追加で出る日を含む)は、「入金・振り分け」と概要に「来月の副業の入金(予想)」として出す。月が替わると、その額が入金予定に自動で入る。入金予定と対応していない依頼元には、同じ名前の入金予定と対応させる(無ければ「副業:依頼元」を作って対応させる)ボタンを出す。

### 価格の自動取得

設定画面の「価格の自動取得(資産)」に入力します。銘柄コードだけを送り、数量や金額は送りません。

- **国内株・投資信託**:設定の URL に `GET ?codes=コード1,コード2` を送る。返事は
  `{ "version": "v6", "results": { "コード": 価格 }, "errors": ["コード"], "errorDetails": { "コード": "理由" } }`。
  `version` が `"v6"` でなければ「URLが古い、または別のものです」と表示し、価格は何も更新しない。
- **米国株**:Finnhub の quote API(`https://finnhub.io/api/v1/quote`)の `c`(ドル)に USD/JPY を掛ける。キーが無いときは、銘柄の編集でドルの株価を手入力する。
- **USD/JPY**:次の順に使う。① 上の URL に為替のコード(既定 `USDJPY`)も一緒に問い合わせる(GAS が為替に対応しているとき)→ ② 返事に無いとき・失敗したときは、キー不要の公開の為替レート:(a) Frankfurter(`https://api.frankfurter.dev/v1/latest?base=USD&symbols=JPY`。欧州中央銀行の基準値。旧 `api.frankfurter.app` は移転して転送になったため変えた)→ (b) currency-api(`cdn.jsdelivr.net/npm/@fawazahmed0/currency-api@latest/v1/currencies/usd.min.json`。毎日更新)→ ③ 設定の手入力値 → ④ 前回使った値のまま。公開の為替レートは平日に1日1回だけ更新される(欧州中央銀行の基準値)ため、同じ日は何回「価格を更新」しても同じ値になる(土日・祝日は前の平日の値)。このことは、価格の更新の結果・資産のダッシュボードの USD/JPY の表示・設定の説明に一文で出す。Finnhub は米国株の株価(ドル)だけに使い、為替には使わない。取れなかったときは、どこで・なぜ取れなかったか(価格取得のURL・Frankfurter・currency-api)を「価格を更新」の結果に出す。どれも無いと、米国株は円に換算できず「価格未取得」(保有の一覧に「USD/JPY が無いため円に換算できません」と出る)。
- URL が無い国内株・投資信託も、銘柄の編集で価格を手入力できる。
- 価格が取れるかは種別(国内株・投資信託・米国株)とコード、URL・キーの設定で決まり、証券会社の違いは関係しない。
- 取れなかった銘柄には理由を付け、「価格を更新」の結果を証券会社ごとに出す。保有の一覧でも、価格の無い銘柄に「取れない理由」を出す(コード未入力 / URL・キー未設定 / 取得失敗の理由 / まだ更新していない)。
- 外部に接続できない場所(claude.ai の試用ページなど)では、自動取得は動かない(「通信できませんでした」と出る)。その場合は手入力する。URL とキーは、開いている画面(ブラウザ)ごとに保存される。

### 株式分割・配当の自動確認

価格の更新(手で押したとき・開いたときの自動更新)のときに、1 日 1 回ほど、価格取得の URL(GAS)に分割と配当の記録を問い合わせ、保有と見比べます(計算は `js/features/assets/events.js`)。

**GAS に足す(最初に 1 回だけ)**:いまの価格取得の GAS は、分割・配当に対応していません。次の手順で足します(パソコンのほうが楽です。スマホなら Safari の「デスクトップ用Webサイトを表示」で)。

1. 価格取得に使っている Apps Script のプロジェクトを開く
2. 左の「ファイル」の ＋ →「スクリプト」で新しいファイルを作り(名前は `events` など)、このリポジトリの [`tools/gas/events.gs`](tools/gas/events.gs) の中身をそのまま貼り付けて保存する
3. いまの `doGet(e)` の **いちばん最初の行** に、次の 1 行を足して保存する
   `if (e && e.parameter && e.parameter.events) return moneyTrackerEvents_(e);`
4. 「デプロイ」→「デプロイを管理」→ 鉛筆 →「バージョン」で「新バージョン」→「デプロイ」(URL は変わらないので、アプリの設定はそのまま)
5. アプリの「資産」→「保有」→「分割・配当の確認」(設定の「価格の自動取得」にもある)→「今すぐ確認」で、「新しい分割・配当の変更はありませんでした」などと出れば使えている

※ Apps Script のエディタで `doGet` を「実行」すると、`TypeError: Cannot read properties of undefined (reading 'parameter')` と出ます。`doGet` はアプリから URL で呼ばれたときだけ動くもので、エディタから実行すると問い合わせの中身(`e`)が無いためです。追加したコードの誤りではありません(確かめるのはアプリの「今すぐ確認」で)。

足していない GAS のときは「対応していません」と出し、7 日ごとに試します(価格の取得はこれまでどおり動きます)。

- **問い合わせ**:`GET ?events=1&codes=X101,US:XYZ&range=2y`(国内株は 4 文字のコード、米国株は `US:` を付けたティッカー。投資信託は問い合わせない)。GAS は Yahoo Finance のチャートの記録(`query1.finance.yahoo.com/v8/finance/chart/…&events=div,splits`)から、分割(日付・`numerator`・`denominator`)と配当(権利落ち日・1株の金額)を返す。返事は `{ "version": "events-v1", "events": { "コード": { "splits": [...], "dividends": [...] } }, "errors": { "コード": "理由" } }`
- **確認を始めた日**:銘柄ごとに、最初に確認した日を `eventsSince` に残す。それ以後の記録だけを「新しい」とみなす(同じ記録は二度扱わない)。銘柄のコードや種別を変えると、最初からやり直す
- **株式分割(併合も)**:確認を始めた日以後の分割は、**自動で反映** する。**数量 = 分割前の数量 × 分割数**(1株 → 3株なら ×3)、平均取得単価・今の株価・1株配当 = 分割前 ÷ 分割数。評価額と取得額は変わらない。価格の更新と同じ書き換えの中で反映するので、総資産の履歴がずれない。併合(10株 → 1株)は分割数 0.1 として同じ計算
- **最初の確認で見つかった分割**(120 日以内):アプリの数量がすでに分割後か分からないため、反映せずに「確認が必要」にする。「反映する」で反映、「反映しない」でそのまま
- **配当**:確認を始めた日以後に新しい配当があり、1株配当が登録と違うときは「提案」にする(勝手には変えない)。配当が未登録の銘柄には、最初の確認で直近 1 年の配当から提案する。「内容を見て反映」で、1株配当と支払月を直してから反映できる。支払月は権利落ちの月からの目安(国内株は 3 か月後、米国株は 1 か月後)。中間と期末で金額が違う会社は、そのたびに提案が出ることがある
- **優待**:内容を自動で取れる公開の仕組みが無いので、自動では確かめない。株数が条件(`minShares`)に足りない銘柄は、「配当・優待」の一覧に「優待の条件に足りません」と出す。分割を反映したときは、優待の条件・内容が変わることがある旨を出す
- **気づくように**:反映したもの・確認が必要なもの・提案は、確認するまで次の所で目立たせる。資産のダッシュボードのいちばん上のお知らせ(黄色)、下部タブの「資産」の赤い点、保有と配当・優待の一覧の行(青い帯と色、分割は「100 → 300株」のように前を消し線・後を色付き)、お知らせの画面の「前 → 後」(変わった所に色)。「確認した」「すべて確認した」で色が消える
- **元に戻す**:反映したものは、お知らせの画面の「元に戻す」で戻せる。分割は、数量・平均取得単価・1株配当を反映前に戻す(反映後に数量などを変えていれば、分割数で割り戻す)。今の株価は、反映後に価格を更新していればそのまま
- **手で反映**:保有の銘柄を押す →「株式分割・併合を反映」で、「1株が何株になるか」を入れて反映できる(前後の値を確かめてから)。お知らせの「これまで」に残り、元に戻せる

### 旧アプリからの取り込み

設定画面から、以前使っていた 4 つのアプリのバックアップを読み込めます。どれも、読み込む前に件数と変換できなかった項目の一覧を確認でき、上書き前のデータは「直前のデータに戻す」で戻せます。

- どのボタンでも、バックアップの書き方を問わず読める:「LZ:」で始まる圧縮(LZ-String)、base64(`atob` + `decodeURIComponent`)、そのままの JSON、旧・支払い管理アプリのテキスト形式(下を参照)
- 中身から、どのアプリのバックアップかを見分ける(`inventory` か `lotteries` → ポケカ、`holdings` → 資産、`jobs` か副業の配列の形 → 副業、`accounts` や `payments` など → 支払い、`app: "money-tracker"` → このアプリの書き出しファイル)。違うボタンで貼ったときは、どのボタンで読むかを出し、貼った文字のまま、その取り込みへ移れる

#### 旧・支払い管理アプリ

設定の「旧・支払い管理アプリのバックアップを読み込む」で、旧形式を変換します。読める形は 2 つです。

- JSON(キー:`accounts`, `wallets`, `incomes`, `payments`, `history`, `specialPayments`, `memos`, `allocations`)
- テキスト形式:`【手元現金】` `【口座】` `【入金】` `【支払い】` `【特別支出】` `【メモ】` `【履歴】` の見出しの下に、カンマ区切りの行が並ぶもの(例は架空)

```
---支払い管理バックアップ---

【手元現金】
1001,財布,30000,0,0,0,駐輪場、日用品          … id,名前,残高,(数値 3 つ),メモ

【口座】
1002,架空銀行A 本店,120000,0,0,               … id,名前,残高,(数値 2 つ),メモ

【入金】
2001,給与,250000,1,0,架空銀行A 本店に入金      … id,名前,金額,毎月固定(0/1),済(0/1),メモ

【支払い】
3001,カードA,80000,26,1002,variable,0,,        … id,名前,請求額,引き落とし日,口座のid,カテゴリ,済(0/1),メモ,終了月
>3101,積立投資,30000,investment,,              … 先頭が「>」:すぐ上の支払いの内訳(id,名前,金額,カテゴリ,終了月,メモ)

【特別支出】
4001,固定資産税,30000,2026-12,0,年4回          … id,名前,金額,支払月,済(0/1),メモ

【メモ】
メモの本文(何行でも)

【履歴】
2026-06,26年6月,100500,90000,20000,500,50000,30000,(base64),258000,(base64)
                                               … 年月,表示名,支払の合計,月末残高,ローン,固定費,変動費,投資,支払いの明細,収入の合計,入金の明細
```

テキスト形式では、次のように読みます。

- 履歴の明細は base64 の JSON(支払い:`{ "loan": [{ "name", "amount" }], "fixed": […], "variable": […], "investment": […] }`、入金:`[{ "name", "amount" }]`)。支払いの明細は、カテゴリつきの 1 つの一覧にする
- 入金のメモが「◯◯に入金」で、◯◯が口座(手元現金)の名前なら、その口座を優先振込先にする
- 口座・手元現金の残高とメモの間の数値は、意味が分からないので読まない(0 以外なら、確認画面のお知らせに出す)
- 履歴の「支払の合計」が、カテゴリ別の合計の和と合わない月は、元の値のまま読み込み、お知らせに出す

どちらの形も、次のように変換します。

- `"1000+500"` のような式の金額は計算して整数にする
- 口座(`accounts`)と手元現金(`wallets`)は、同じ名前の月末記録の項目があればつなぎ、無ければ「現金(銀行口座)」区分に項目を作る
- 手元現金の支出予定(`outgoAmount`)は、支払い「◯◯の支出」として取り込む
- 口座のメモは支払い管理のメモにまとめる。口座ごとの入金予定額(`incomingAmount`)は振り分けから計算するため取り込まない
- 変換できなかった項目(読めない金額・見つからない口座・不明なカテゴリなど)は一覧で確認できる
- 置き換わるのは支払い管理の区画だけ

#### 旧・資産管理アプリ

設定の「旧・資産管理アプリのバックアップを読み込む」で、旧形式(`holdings`, `history`, `prices`, `lastTotal`)の JSON を変換します。

- 口座区分 `特定` / `一般` はそのまま。`NISA` は旧 NISA か新 NISA か分からないので、仮に新 NISA にして、読み込み後に選び直す一覧を出す(資産のダッシュボードにも案内が出る)
- 種別 `JP` / `US` / `FUND` を 国内株 / 米国株 / 投資信託 に。数量・取得単価が式や文字列でも計算する
- はっきりしない点は確認画面で選ぶ:投資信託の数量が「口数そのまま」か「口数 ÷ 1万」か(`lastTotal` に近くなる方を初期値に)、米国株の平均取得単価が円かドルか
- `prices` は「旧アプリの価格」として入れる(日時は不明。「価格を更新」で新しくなる)。`history` の日付 `YYYY/M/D` は `YYYY-MM-DD` に
- 置き換わるのは「保有」と「履歴」だけ。手入力の資産と設定は残る

#### 旧・副業管理アプリ

設定の「旧・副業管理アプリのバックアップを読み込む」で、JSON(.txt でも可)を変換します。次の 3 つの形を自動で見分けます。

- `[設定配列(6要素), 記録配列]`:設定は `[A名, A基本額(万), A内容, B名, B基本額(万), B内容]`、記録は `[yymmdd, 0=A/1=B, 金額(万), 入金確認0/1, 内容]`(内容は文字列、または 1 = A の既定内容 / 2 = B の既定内容)
- `[記録配列, 設定配列]`:記録は `[id, "YYYY-MM-DD", "A"/"B", 金額(万), 入金確認, 内容]`
- `{ jobs: [...], settings: { companyA, companyB } }`:`status` が `"done"` なら入金確認済み、`"plan"` なら未確認

万円の小数は文字列のまま桁をずらして円の整数にします(誤差が出ない)。過去の記録の内容は文章のまま残し、作業項目には分けません。旧アプリの既定の内容は依頼元のメモに入れます。副業の依頼元・記録・予定は置き換わります。

#### 旧・ポケカ管理アプリ

設定の「旧・ポケカ管理アプリのバックアップを読み込む」で、.txt を変換します。

- 先頭が `LZ:` なら LZ-String(CDN の lz-string 1.5.0)の `decompressFromBase64` で展開、そうでなければ `atob` と `decodeURIComponent` で戻す
- 中身の JSON から `inventory` だけを読む(`lotteries`・`settings`・`suggests`・`productMasters`・`sheetMeta` は読み込まない)
- 売却時点の購入単価は旧データに無いため、今の購入単価で記録する。売却優先度はすべて「最初に売る」
- 在庫の商品は置き換わります(反映先の設定は残ります)

## Excel の過去記録の取り込み

設定の「Excel の過去記録を取り込む」から、2 種類の表を取り込めます。どちらも、取り込む前の確認画面で中身を見てから書き込みます。確認画面の「例の表を入れる」で、下の架空の表をそのまま試せます。

### 入力のしかた

- **貼り付け**:Excel で表の範囲を選んでコピーし、貼り付ける(タブ区切り)。カンマ区切りのテキストも読める
- **CSV ファイル**:UTF-8 と Shift_JIS のどちらも読める(自動で見分ける。文字が化けたら文字コードを選び直す)

### 表の読み方(A・B 共通)

- 1 列目が項目名(カード名)、2 列目以降が月ごとの金額。記号(●など)だけの列と、項目名が空の行は無視する。項目名の先頭の記号も外す
- 金額の入った最初の行より上は見出しの行。見出しの文字は確認画面に出すだけで、**月名には頼らない**。確認画面で「最初の月列の年月」を指定し、右へ 1 列ごとに 1 か月ずつ進める(見出しが「#####」でも読める)
- 見出しに「合計」「年間」「平均」を含む列は、最初はオフで、月として数えない(オンにすると月として数える)。全部空欄の列も最初はオフ(月としては数える)。列は確認画面で 1 列ずつオン/オフできる
- 金額:「1,234」「¥1,234」は整数、「-」と空欄は未入力(今の値は変えない)、「0」は 0。マイナスは「-1,234」「△1,234」「▲1,234」「(1,234)」。小数は円に丸める。読めない値は空欄として扱い、確認画面に一覧を出す

### A. 月末記録(口座資産の表)

取り込める表の例(架空):

| 口座 | 2025年 | | | 2026年 | | | |
|---|---|---|---|---|---|---|---|
| | 10月 | 11月 | 12月 | 1月 | 2月 | ##### | 年間平均 |
| 架空銀行A 普通 | 412,000 | 398,500 | 455,300 | 430,800 | 468,200 | | 432,960 |
| 架空信用金庫 定期 | 1,000,000 | 1,000,000 | 1,000,000 | 1,000,000 | 1,000,000 | | 1,000,000 |
| 証券X 特定口座 | 820,000 | 845,300 | 801,200 | 868,900 | 902,400 | | 847,560 |
| 証券X NISA | 560,000 | 598,200 | 617,500 | 664,300 | 702,800 | | 628,560 |
| サークルの預かり金 | 36,000 | 48,000 | 12,000 | 24,000 | - | | 30,000 |
| 合計 | 2,828,000 | 2,890,000 | 2,886,000 | 2,988,000 | 3,073,400 | | 2,933,080 |
| 前月比 | - | 62,000 | △4,000 | 102,000 | 85,400 | | |
| 含み益 | 210,000 | (12,000) | 198,000 | 250,300 | 301,000 | | |

最初の月列を「2025年10月」にすると、10月〜2月の 5 か月を取り込みます(「#####」の列は全部空欄なので外れ、「年間平均」は合計などの列なので数えません)。

- **行の扱い**(確認画面で 1 行ずつ直せる)
  - 名前に「合計」「総資産」「前月比」「月平均」を含む行 → 取り込まない(計算で出す)
  - 合計の行(名前が「合計」「総合計」「総資産」など。無ければ「合計」を含む最初の行)より下の行と、名前に「含み益」を含む行 → 参考行(項目として記録するが、小計・総資産に含めない)
  - それ以外 → 取り込む。既存の項目名と一致すれば(空白の違いは無視)その項目へ、無ければ新しい項目として追加
- **区分**:新しい項目は行ごとに選べる。最初は、名前に「預かり」→ 預かり金、「銀行」「信用金庫」「JA」→ 現金、それ以外 → 投資(まとめに入る行は、そのまとめの行でいちばん多い区分。「架空証券(預かり)」も証券会社と同じ区分になる)。既存の項目へ書くときは、その項目の区分のまま
- **まとめ**(証券会社など):行ごとに選べる(まとめなし / 今あるまとめ / 新しいまとめを作る)。最初は、「架空証券(国内株式)」「架空証券(米国株式)」のように括弧の前が同じ行が 2 行以上あれば、それをまとめにする。括弧の前がまとめの名前の始まりと同じ行(「架空(預かり)」と「架空証券」)もそのまとめへ(当てはまるまとめが 2 つ以上なら入れない)。既存の項目へ書くときは、その項目のまとめが最初の選択。参考行にはまとめを付けない
- **二重に数える項目**:今ある項目(参考行でないもの)の名前が取り込むまとめと同じで、取り込む月に値があると、確認画面で知らせる(「架空証券」の 1 行で記録していた所へ、内訳を取り込む場合)。取り込んだあと、項目の編集で今の項目を削除すると、総資産が元の表と同じになる
- **確認**:月ごとに、取り込む行だけで区分小計と総資産を計算して見せ、元の表に合計の行があれば、その数字との差を出す。同じ項目に 2 行を対応させたときなどは、理由を出して取り込めないようにする
- **すでに値がある月**:月ごとに「上書き(表の値で置き換える。表が空欄の所は今の値のまま)/ スキップ / 空欄だけ補う(既定)」を選ぶ。確認画面から、取り込む前に今のデータを JSON に書き出せる
- **書き込み**:無い月は作る(前月のコピーはしない)。書き込んだ値は、取り込んだ日を確認日・最終更新日にする

### B. カード推移(任意)

取り込める表の例(架空):

| カード | 2025年 | | | 2026年 |
|---|---|---|---|---|
| | 10月 | 11月 | 12月 | 1月 |
| カードA | 52,300 | 48,900 | 61,200 | 45,800 |
| カードB | 12,400 | 9,800 | 15,600 | 11,200 |
| カードC(家族) | - | 3,200 | 0 | 4,500 |
| 架空銀行A 合計 | 64,700 | 58,700 | 76,800 | 57,000 |
| 架空銀行B 合計 | - | 3,200 | 0 | 4,500 |
| 総合計 | 64,700 | 61,900 | 76,800 | 61,500 |
| 前月比 | - | △2,800 | 14,900 | △15,300 |

- 入力のしかた・金額の読み方・月の指定は A と同じ
- 名前に「合計」「総合計」「前月比」「月平均」を含む行は取り込まない。「合計」を含む引き落とし口座別の行(上の「架空銀行A 合計」など)は、確認画面に参照用として表示だけする。元の表の総合計(「総合計」「合計」などの行)と、取り込む行の合計の差も出す
- 取り込み先は、支払い管理の月別履歴の「支払いの明細」。カテゴリは行ごとに選べる(最初は変動費)。カテゴリ別の合計と支払の合計も合わせて直す
- その月の履歴が無ければ作る:収入は未入力、月末残高は月末記録の「現金」区分の小計(その月に値が無ければ未入力)
- 履歴が既にある月は、月ごとに「上書き(同じ名前の明細を置き換える。ほかの明細と収入はそのまま)/ スキップ / 空欄だけ補う(同じ名前の明細が無いものだけ足す。既定)」を選ぶ

### 履歴と元に戻す

- 取り込むたびに、日時・種類・月・件数・ファイル名を履歴に残す(設定に直近 5 件を表示。データには 30 件まで)
- 「直前の取り込みを元に戻す」で、直前の 1 回を取り消せる。月末記録は、書き込んだ所を取り込む前の値・確認日に戻し、追加した項目と、取り込みで作って空になった月を消す(参考行の印も戻す)。カード推移は、作った月の履歴を消し、書き換えた月を取り込む前に戻す
- 取り込んだあとに同じ所を手で直していた場合は、その変更も戻る(確認ダイアログに出す)。取り込みと元に戻すの前には、ふだんの「直前のデータに戻す」用の控えも保存する

## 将来予想(ライフプラン)

「その他」→「将来予想」(`#/future`)。下部タブは 5 つまでのきまりなので、「その他」の中に置いています。どの画面にも「仮定にもとづく予想で、将来を保証するものではありません」を小さく出します。

### プラン

- 条件のまとまりを「プラン」として保存する(最大 10 件)。名前の変更・複製・削除ができ、「比較」で 2 つを選んで並べる(例:車を買い替える / 買い替えない)
- はじめは「最新の記録からプランを作る」で、下の初期値を入れて作る。どの値も手で直せる

### 入力する条件

| 条件 | 中身 | 最新の記録からの初期値 |
|---|---|---|
| 基本 | 計算の開始年月(今の資産の時点)、生年月(または今の年齢から逆算)、予想の期間(既定 40 年)、インフレ率(既定 0%) | 開始年月 = 今月 |
| 収入 | 手取りの月額を「何歳から何歳まで、月いくら」で複数行(働く期間・再雇用・年金など)。年齢の空欄は「今から」「期間の終わりまで」 | 支払い管理の入金予定のうち、副業から自動で入るもの以外で、「毎月固定」で金額のあるもの(その額)と、支払いの履歴の直近 3 か月に毎月同じ名前で入っているもの(その平均。「変動」で月替わりに空欄になった給与など)。年齢の条件なし。「記録から足す」で、あとからも足せる |
| 臨時収入 | 名前・年・月・金額(手取り)。「毎年なら最後の年」を入れると、その年まで毎年 | なし |
| 副業収入 | 月いくら・いつまで | 副業の直近 6 か月(今月を除く)のうち、記録のある月の平均 |
| 家族などからの返済 | 名前・月額・終了年月(その月まで) | なし。「入金予定から選ぶ」で名前と金額を引ける |
| 毎月の生活費(ローン・積立を除く) | 今の月額と、年齢による変化(「何歳から月いくら」) | 支払い管理の履歴の直近 3 か月の、固定費 + 変動費の平均(ローン・投資・特別支出を除く)。履歴が無ければ今月の固定費 + 変動費 |
| ローン | 名前・月額・開始年月(任意)・終了年月(その月まで払う) | 支払い管理のカテゴリ「ローン」の支払い・内訳と、その終了月。終了月の無いものは終了年月が未入力のまま入れ、注意を出す |
| 積立投資 | 毎月の積立額(現金 → 投資)、開始・終了、口座区分(課税口座 / NISA / 税金を計算しない)、取り崩すときの優先度 | 支払い管理のカテゴリ「投資」の支払い(課税口座・足りなければ売る) |

### 今の資産(初期値)

- **現金**:月末記録の最新月の「現金(銀行口座)」区分(`cat_cash`)の小計。支払い管理の口座の現在残高の合計や、手入力にも切り替えられる
- **投資**:資産管理の保有(価格の取れている銘柄。価格未取得の銘柄は入れず、件数を知らせる)と手入力の資産、ポケカ在庫(個数 1 以上)の評価額。売却優先度(最初に売る / 足りなければ売る / 売りたくない)と取得額(税金の計算用)を引き継ぐ
  - 株・投信:利回りで増える。特定・一般は課税口座、NISA は NISA
  - 手入力の資産・ポケカ在庫:増えない(利回り 0)。税金は、手入力の「投資」区分だけ課税口座、ほかは計算しない
- 「最新の記録から読み直す」で、現金と投資の一覧を最新の値で置き換える(計算の開始年月も今月に)。ローン・積立は「支払い管理から拾い直す」(手で足した行は残る)、生活費・副業はそれぞれ「計算し直す」

### 計算のきまり

- 内部は**月ごと**に計算し、表は暦の年ごとにまとめる(最初と最後の年は一部の月だけのことがある)。ローンの終了月などは月単位で反映する
- 毎月:**現金 += 収入 − 生活費 − ローン − 積立 − 毎年の費用 − 単発の出費**。積立分は投資に加える
- 投資は、年利から換算した**月利((1 + 年利)^(1/12) − 1)**で月初の残高を増やしてから、その月の積立を足す。現金・手入力の資産・ポケカ在庫は増えない
- ローンは終了年月の月まで払い、**翌月から支出が減る**
- インフレ率は、生活費・毎年の費用・単発の出費(どれも今の値段で入力)に、経過した月数に応じて掛ける((1 + 率)^(月数 ÷ 12))。収入・ローン・積立には掛けない
- 年齢 = 生年月から数えた満年齢(その年齢になった月から次の年齢の前の月まで)。生年月が無いと、年齢の条件つきの行は入らず、注意を出す
- **取り崩しの順番**:取り崩しの対象(オン)の資産を、上から順に売る。既定は「最初に売る」→「足りなければ売る」(同じ優先度は一覧の順:資産 → 積立分 → 現金から戻した分)で、「売りたくない」はオフ。条件の「取り崩す資産と順番」で入れ替え・オン/オフができる
- **毎月の取り崩しの順番**:収入・支出 → 投資を増やして積立を足す → 定額・定率 → 不足分 → 現金の上限を超えた分を投資へ
  - **不足分だけ**:現金が生活防衛資金を下回る月に、生活防衛資金まで戻す(これまでと同じ)
  - **定額**:定額・定率の期間(年齢)のあいだ、毎月その額(売る額)を売る
  - **定率**:年初(1月か計算の最初の月の、増える前)の取り崩しの対象の残高 × 率 ÷ 12(円に丸める)を、その年の毎月売る
  - **併用**:「不足分も補う」なら、定額・定率のあとで現金が生活防衛資金を下回れば不足分も取り崩す。補わない設定なら、足りない月は資金不足になる。期間の外(開始前・終了後)は「不足分だけ」
  - **1年あたりの上限**:1〜12月に売る額の合計がこの額まで。定額・定率は上限で止まる。必要な不足分が上限のために取り崩せない月は、隠さず**資金不足**として記録する(理由:上限)
  - **現金の上限**:現金がこの額以上の月は定額・定率を休む。「超えた分を投資に戻す」なら、上限を超えた分を課税口座の投資(現金から戻した分)に移す
- **税**:売った額 × 含み益の割合((評価額 − 取得額)÷ 評価額)× 税率。手取り(売った額 − 税)が現金に入る。手取りで必要額になるよう、売る額 = 必要額 ÷(1 − 含み益の割合 × 税率)を切り上げる。売った割合だけ取得額を減らす
- 取り崩しても現金がマイナスの月と、上限のために必要な不足分を取り崩せない月は**資金不足**、生活防衛資金を下回る月は**防衛資金割れ**として記録する
- 利回りの 3 パターンを同時に計算する。金額は毎月、円の整数に丸める

### 表示

- **最初の1年の内訳(月平均)**:入ってくるお金(収入・副業・返済・臨時収入)と出ていくお金(生活費・ローン・毎年の費用・単発の出費・積立)、現金の増減と「積立を除くと」の差し引き。予想がすぐマイナスになるときに、どの値が原因かを見るため。収入が入っていない・積立を除いても赤字のときは注意を出す
- **要約**:パターン別に「資金が足りなくなる年(なければ“期間内は大丈夫”)」「期間の終わりの総資産」「生活防衛資金を割る最初の年」「取り崩しの合計(手取り)」
- **グラフ**:総資産の推移(3 パターンを 3 本の線。資金が足りなくなる年に赤い ▲)と、現金と投資の積み上げ棒(選んだパターン)の切り替え。線の右端に名前を直接書く

- **原因**(`#/future/why`。選んだパターンで):
  - **資金不足の原因**:資金不足が最初に出る年の内訳(年初の現金・収入・生活費・ローン・積立・毎年の費用・単発の出費・取り崩し・上限で取り崩せなかった額・年末の現金・年末の取り崩せる資産)を、前の年と並べて差を出す(支出の行は増えると赤)。考えられる理由(上限・取り崩せる資産がない・不足分を補わない設定・収入の減少・生活費やローンの増加・その年の単発の出費)も出す
  - **ちょっと変えたらどうなる**:生活費 ±30%、収入の終わり ±5 年(「何歳まで」のある収入の終わりと、続けて始まる収入の始まりを同じだけずらす。年金など終わりの無いものは動かさない)、積立額 ±100%、利回り ±3 ポイントをスライダーで動かし、資金が足りなくなる年と期間の終わりの総資産をすぐに出す。保存はせず、「この条件で保存」で今のプランに書き込む(直前のデータに戻せる)
  - **10% 変えたときの影響**:収入・副業・臨時収入・返済・生活費・ローン・毎年の費用・単発の出費・積立額・利回り・インフレ率・今の現金・今の投資資産・定額 / 定率の値を、それぞれ +10% / −10% したときの期間の終わりの総資産の差を、影響の大きい順に。資金不足の年が変わる項目は、変わったあとの年月も出す
- **比較**:プラン A と B(それぞれのプランの同じパターンの利回り)の総資産の推移を 2 本の線で。要約と、年末の総資産の差(B − A)の表

## データとプライバシー

- **データは各自の端末のブラウザの中(localStorage)にだけ保存されます。** サーバーには送りません。開発者を含め、ほかの人がデータを見ることはできません
- **iPhone では、ホーム画面から開いた場合と Safari で開いた場合で、データが別になることがあります。** ふだん使う方を決めてください。移すときは、移す前の方で「バックアップ」→ 移した先で「バックアップから戻す」
- ブラウザの「履歴と Web サイトデータを消去」や、長いあいだ開かないことで、データが消えることがあります。月に 1 回はバックアップしてください
- 価格取得の URL とキーは、データ本体とは別に保存し、バックアップには既定で含めません(書き出すときに選べます)

### バックアップの取り方と戻し方

1. **取り方**:設定のいちばん上「バックアップ(全データを書き出す)」を押す。iPhone では共有シートが出るので「"ファイル"に保存」を選び、iCloud Drive などに保存する(ファイル名 `money-tracker-年-月-日.json`)
2. **戻し方**:設定の「バックアップから戻す」でファイルを選ぶ。中身を確かめる画面が出るので「読み込む」。いまのデータは上書きされる前に 1 つ控えを取るので、間違えたら「直前のデータに戻す」で戻せる
3. 最後のバックアップから 30 日以上たつと、設定・月末チェック・起動時の案内で知らせる

### 公開リポジトリに実データを入れない

- コード・テスト・サンプル・README には、架空のデータだけを入れる(実際の金額・個人名・口座名・金融機関名・会社名・URL・API キー・スプレッドシート ID を入れない)
- バックアップや書き出したファイル、旧アプリのデータ、Excel の表は、リポジトリのフォルダに置かない。置いてしまっても `.gitignore` でコミットされないようにしてある(`*.json` `*.txt` `*.csv` `*.tsv` `*.xlsx` `*.xls` `*.zip` `*.bak` `money-tracker-*` など)。サンプルとして必要なファイルは `名前.sample.json` のように名付ければ除外されない
- 段階6の点検:実在の名前・金額・URL・キー・スプレッドシート ID・バックアップファイルが無いことを確かめた(過去のコミットのコメントに実在の名前が 1 か所あり、いまの版では直した。「[次にやること](#次にやること)」の 3)

## ホーム画面から使う(PWA)

1. iPhone の Safari で公開した URL を開く → 共有ボタン → 「ホーム画面に追加」
2. ホーム画面のアイコンから開くと、アドレスバーのない画面で開く(上下の安全領域・ホームバーと下部タブが重ならないようにしてある)
3. 一度開いたあとは、電波がなくても開ける(価格の更新など、通信が要る操作はできない)
4. 新しい版は、次に開いたときに入れ替わる。古い画面のままのときは、設定の「アプリの更新」→「最新版に更新」(データは消えない)
5. 金額の欄で数字キーボードに + − × ÷ が出ないときは、欄の下(小さい欄では入力中に出る)の + − × ÷ のボタンを使う

4. **ホーム画面に追加**:共有ボタン →「ホーム画面に追加」。いま使っている場所(試用ページなど)からデータを移すときは、そちらで「バックアップ」→ ホーム画面のアプリで「バックアップから戻す」
